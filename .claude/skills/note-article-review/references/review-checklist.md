# 詳細レビューチェックリスト

このファイルは note-article-review skill から参照される、詳細なレビュー観点。

## 1. タイトル

### 必須要素チェック
- [ ] 対象データ・対象エリアが具体的に明示されているか（「東京23区」「築年数別」「2020-2025年」など）
- [ ] 切り口を示す動詞・名詞が入っているか（「乖離」「逆転」「相関」「再分布」「矛盾」など）
- [ ] 時間軸・期間が示されているか

### NGパターン
- 「〇〇について解説します」型（答えを先に出している）
- 「私が△△して分かった〇〇」型（自己啓発系）
- 「絶対知るべき〇〇の真実」型（toC煽り系）
- 「初心者向け〇〇入門」型（業界人向けと矛盾）
- 一般化されすぎたタイトル（「不動産市場の今後」のような何でも書けるタイトル）

### 強いタイトルの例
- 「東京23区の家賃と世帯年収の乖離マップ：2015-2025年の10年変化」
- 「タワマン価格上昇の主役は誰だったか：購入者属性データから読む2020-2025」
- 「人口減少エリアで家賃が上がっている矛盾：地方中核都市30エリアの定量分析」

---

## 2. 冒頭ブロック（最初の300-500字）

### 必須要素
- [ ] 業界で疑問視されているが定量化されていない事象を提示しているか
- [ ] 既存の言説の問題点（雑な仮説、データなしの直感論）に触れているか
- [ ] この記事で使うデータと分析方法が予告されているか
- [ ] 冒頭3行で「読み続ける価値」が示されているか

### NGパターン
- 「こんにちは。今日は〇〇について書きます」（定型句）
- 自己紹介から始まる（自慢に見える、本文で語るべき）
- 「皆さんご存知の通り」（読者の知識を仮定しない）
- 業界の歴史から始まる教科書的導入（業界人には冗長）
- 「最近〇〇が話題ですが」（メディア二次情報の引用は弱い）

### 強い冒頭の構造
1. 業界で語られているが定量化されていない事象を1-2文で提示
2. なぜそれが定量化されていなかったかの理由（データの分散、視点の欠如など）
3. この記事で使うデータと、得られた発見の予告（ネタバレしすぎず）

---

## 3. 章立て構造（H2見出し）

### 必須要素
- [ ] 動詞または完結した命題で見出しが書かれているか（「〇〇について」型ではない）
- [ ] 各章が独立した小ストーリーとして読めるか
- [ ] 章の順序に必然性があるか（並び替えても成立してしまう構成は弱い）
- [ ] 章数が5-7章程度に収まっているか

### NGパターン
- 「はじめに」「まとめ」のような汎用見出し
- 「〇〇とは」（定義の章は業界人記事では不要）
- 「メリット」「デメリット」（両論併記の典型）
- 番号のみ（「1. 〇〇 2. △△」）で内容が見出しに表れていない

### 強い見出しの例（樫田光モデル参考）
- 「LTVの概念を導入した」
- 「アサイン性のチーム構成にした」
- 「ダッシュボード文化を根付かせた」

不動産データジャーナリズム向けに翻訳すると：
- 「家賃と所得の乖離が顕著なのは港区だった」
- 「築年数別の家賃下落カーブは2010年を境に変わっている」
- 「人口減少と家賃上昇が共存するエリアを特定した」

---

## 4. 各章の内部構造

### 推奨パターン（樫田モデル）
1. 当時の業界の問題状況・通説の描写（共感ポイント）
2. データで何を見たか・分析の切り口
3. chart の提示
4. 結果と発見（特に通説と異なる部分）
5. 含意・解釈

### チェック項目
- [ ] 各章に chart が1-2枚配置されているか
- [ ] 章の冒頭1-2文で章の論点・視点が明示されているか
- [ ] 太字は章ごとに1-2箇所程度に絞られているか（多すぎないか）
- [ ] 段落が3-5行で区切られているか（スマホ読みやすさ）
- [ ] 一文が60字以内に収まっているか

---

## 5. 「考えた跡」の有無（最重要）

業界人向け記事の最大の価値は、書き手の思考プロセスが見えること。以下が含まれているか確認：

- [ ] なぜこの切り口を選んだかの言及
- [ ] 他の分析方法と比べて何が見えるかの説明
- [ ] データの限界の明示（誠実さ）
- [ ] 通説との違いに対する書き手の解釈
- [ ] 業界経験・現場感覚との照合

### AIっぽさのチェック（要排除）

以下の特徴があれば、AIで生成されたまま放置されている可能性が高い：

- 接続詞の不自然な多用（「さらに」「また」「しかしながら」が等間隔）
- 結論の留保癖（「〜と言えるでしょう」「〜と考えられます」「〜の可能性があります」の連発）
- 何でも箇条書き
- 定義から入る章が複数ある
- 「重要です」「興味深い」「注目すべき」の多用
- 両論併記で立場が見えない
- 具体例が抽象的・架空（「ある不動産会社では」型）
- 段落の長さが均一すぎる
- 各章が同じ構造で繰り返されている

---

## 6. データ・chart の扱い

### チェック項目
- [ ] chart のキャプションが「何を示しているか」明確か
- [ ] データソースが明示されているか（不動産情報ライブラリ、e-Stat、国土数値情報など）
- [ ] データ取得時点・集計期間が明記されているか
- [ ] サンプルサイズ・カバレッジが示されているか
- [ ] chart 単体で見ても意味が伝わる設計になっているか（タイトル・軸ラベル・凡例）
- [ ] 「これは X 用に切り出せる」と思える chart があるか

### NGパターン
- chart が補助的にしか使われていない（本文がメインで chart はおまけ）
- データソースの明示がなく、信頼性が担保されていない
- chart の解釈が本文と乖離している
- 業界人がすでに知っている当たり前の chart（既存メディアで見飽きたもの）

---

## 7. 結論・含意

### チェック項目
- [ ] 書き手の立場が明確か
- [ ] 業界の通説とどう違うかが述べられているか
- [ ] 次の問い（未解決のテーマ）が提示されているか
- [ ] 「結局よく分からなかった」型で終わっていないか

### 推奨される結びの構造
1. データから得られた具体的発見の要約（1-2文）
2. これが業界に与える示唆（1-2文）
3. データの限界・残された問い（1-2文）
4. 次に分析したいテーマの予告（任意、1文）

---

## 8. 末尾の付加情報

### 必須要素
- [ ] データソースの明示（信頼性の担保）
- [ ] 分析手法の概要（再現性の担保）
- [ ] 分析の限界の明示（誠実さ）

これらは「業界人が引用・転載する際に必要な情報」として機能する。

---

## 9. X投稿用抜粋候補の発見

レビュー時に、note記事の中から **X用にそのまま使える / 切り出して強くなる箇所** を発見する。以下の形式で：

- chart 1枚 + 1行キャプション型（最強）
- データの意外性が出ている1-3文
- 業界通説への辛辣な批評（あれば）
- 視覚的な比較（「Aは X、Bは Y」型）

各候補について、「なぜ X で刺さるか」を1行で添える。

---

## 10. 文体・トーンの最終チェック

- [ ] 業界人として対等な目線で書かれているか（上から目線でも、媚びでもない）
- [ ] 断定すべきところで断定しているか
- [ ] 不明な部分は明示的に「不明」と書いているか
- [ ] エモーショナルな表現が排除されているか
- [ ] 「読みやすさのための補助線」と「読者を子供扱いする冗長な説明」が区別されているか
