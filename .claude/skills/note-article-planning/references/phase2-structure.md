# Phase 2: 構成モード

切り口は決まり、章立てを練りたい段階。

## このフェーズのゴール

執筆を開始できる状態の構成メモを作ること。具体的には：

- タイトル（仮）
- 冒頭ブロックの論点
- 章立て（5-7章、見出しと各章の論点）
- chart の配置
- 結論で言いたいこと

## 前提

このフェーズに入る前に、Phase 1 の構想メモが完成しているのが理想。なければ、ユーザーに以下を確認してから始める：

- コアメッセージは何か（1文で）
- 主要な発見は何か（3-5個）
- chart は何枚あるか、それぞれ何を示しているか

## 進め方

### Step 1: タイトルの仮置き

正式なタイトルは執筆後に決めるとして、執筆の方向性を固定するための仮タイトルを作る。

3-5個の仮タイトル案を出す。各案は以下の3要素を含む：

1. 対象データ・対象エリア（具体的に）
2. 切り口を示す動詞または名詞（「乖離」「逆転」「相関」「再分布」「矛盾」など）
3. 時間軸・期間

提示の仕方：

```
仮タイトル候補：
A. 「{案A}」 - {何を強調するか}
B. 「{案B}」 - {何を強調するか}
C. 「{案C}」 - {何を強調するか}
```

ユーザーに「どれが一番自分が書きたい記事に近いか」を選んでもらう。

選ばれた仮タイトルが、執筆中の北極星になる。

### Step 2: 冒頭ブロックの論点設計

冒頭300-500字に入れる3要素を、論点レベルで決める：

1. **業界で疑問視されているが定量化されていない事象**：何を提示するか
2. **既存言説の問題点**：何を批判するか
3. **本記事の予告**：使うデータと、得られた発見の予告（ネタバレしすぎず）

ユーザーに問う：「冒頭で読者を引き込むとしたら、どの違和感から入るのが一番強そうか」

3つの選択肢を提示し、選んでもらう。

### Step 3: 章立ての設計

ここが最も重要かつ時間をかけるべきフェーズ。

#### 章立てのアプローチ

3つのパターンを並べて提示する：

**パターンA：時系列展開**
データの変化を時間軸で追う構成。歴史的経緯を重視する記事に向く。

**パターンB：レイヤー展開**
全体像 → セグメント分解 → 特定セグメントの深掘り、と解像度を上げていく構成。マクロからミクロへ。

**パターンC：仮説検証展開**
業界通説を提示 → データで反証 → 別の仮説を提示 → 検証、と論理を積み上げる構成。

それぞれのパターンで仮の章立てを4-6個提示する。ユーザーに「自分のデータと言いたいことに合うのはどれか」を判断してもらう。

#### 各章の論点詰め

選んだパターンで章を決めたら、各章について以下を詰める：

- **章タイトル（仮）**：動詞または完結命題で
- **章で扱う論点**：何を示し、何を言うか（2-3行）
- **使う chart**：どれを配置するか
- **この章でユーザーが書きたい『考えた跡』**：書き手独自の視点・違和感・現場感覚

最後の項目が最重要。各章に最低1つ、書き手にしか書けない要素を埋め込む計画を作る。

**質問パターン**：

- 「この章で、データだけでは出てこない、自分の現場感覚で言えることは何か」
- 「この章を読んだ業界人が『なるほど』と思うのは、どの部分になりそうか」
- 「この章のここは、自分が業界経験から強く言えるが、他の人には書けない、という箇所はあるか」

### Step 4: chart の配置検討

各 chart について以下を確認：

- どの章に置くか
- chart のキャプション（仮）
- chart 単体で見たときに伝わるメッセージは何か
- X 用に切り出すならどの chart が強そうか（3-5個ピックアップ）

ユーザーが用意した chart の枚数が章数に対して多い・少ない場合：

- 多い場合：「この chart は本記事に必須か、それとも次の記事に残しておけるか」を問う
- 少ない場合：「ここに chart があると説得力が増すが、データから作れそうか」を提案

### Step 5: 結論の方向性

結論で言いたいことを4段構造で詰める：

1. **発見の要約**：データから得られた具体的事実（1-2文）
2. **業界への示唆**：この発見が何を意味するか（1-2文）
3. **データの限界**：本データで捉えきれていないこと（1-2文）
4. **次の問い**：未解決テーマの予告（任意、1文）

ユーザーから引き出すべきこと：

- 「業界への示唆として、自分が一番言いたいことは何か」
- 「データの限界として、批判されそうな部分を先回りで認めておくべきところはあるか」
- 「この記事の続編として、次に書きたいテーマはあるか」

## このフェーズの終わりに出力するもの

執筆開始のための構成メモを以下のフォーマットでまとめる：

```markdown
## 構成メモ

### 仮タイトル
{選択した仮タイトル}

### 冒頭ブロック（300-500字）の3段構成
- 段落1: {業界で疑問視されている事象}
- 段落2: {既存言説の問題点}
- 段落3: {本記事の予告と使うデータ}

### 章立て

#### 章1: {仮見出し}
- 論点: {2-3行}
- chart: {使用する chart}
- 考えた跡として埋め込む要素: {書き手独自の視点}

#### 章2: {仮見出し}
- 論点: ...
- chart: ...
- 考えた跡として埋め込む要素: ...

(章3-5以降同様)

### 結論セクション
1. 発見の要約: {1-2文}
2. 業界への示唆: {1-2文}
3. データの限界: {1-2文}
4. 次の問い: {任意}

### chart 一覧と配置
- chart 1: {何を示すか} → 章{N}
- chart 2: ...
- X 用候補: chart {N}, {N}, {N}

### 末尾の付加情報
- データソース: {取得時点を含む}
- 対象エリア・期間: 
- サンプルサイズ・カバレッジ: 
- 分析手法: 
- 分析の限界: 

### 執筆時の自己注意
- {このフェーズの議論で出た「気をつけたいこと」}
```

これで執筆を開始できる状態。

## このフェーズで避けるべきこと

- **章立ての押し付け**：パターンA/B/Cを提示するが、決めるのはユーザー
- **見出しの代筆**：見出し候補を出すのは可、ユーザーが選ぶ
- **章ごとの「考えた跡」をAIが捏造する**：これはユーザーから引き出すもの
- **完璧主義**：仮の状態で執筆に入る方が良い場合が多い。書きながら調整する前提で良い

## 詰まったときのテクニック

ユーザーが「章立てが決まらない」と言った場合：

1. 章数を減らす提案：「7章を考えているが、本当に必要な核は3つくらいでは。残りは省くか統合できるか」
2. 一番強い章から始める：「全部の章を考えずに、一番書きたい章だけ詳細化してみては。残りはその章を起点に逆算で決まる」
3. 結論から逆算：「結論で言いたいことが決まっているなら、そこに至るための最短の章立ては何か」

ユーザーが疲れているサインを感じたら、構成メモの「未確定」項目を残したまま執筆フェーズに進む提案をする。書きながら詰める方が早いことも多い。
